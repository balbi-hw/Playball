# PLAYBALL | KBO 예측 플랫폼

[日本語](./README.ja.md)

> **공개 범위**: SSAFY 정책에 따라 프로젝트 소스 코드를 외부 저장소로 반출할 수 없습니다. 따라서 이 저장소에는 서비스와 기술 설계를 소개하는 README 문서만 공개합니다. 코드와 화면 캡처는 포함하지 않습니다.

PlayBall은 KBO 경기 정보를 살펴보고 결과를 예측해 참여하는 블록체인 기반 스포츠 서비스입니다. 사용자는 지갑으로 베팅 내용을 서명하고, 참여 기록과 결과 확정, 배당·환불을 스마트컨트랙트에서 확인할 수 있습니다.

## 1. 전체 서비스 흐름

| 단계 | 사용자 경험 | 시스템 처리 |
|---|---|---|
| 경기 탐색 | 경기 일정, 상세 정보, 참여 현황 확인 | 공개 경기·마켓 정보 제공 |
| 정보 확인 | 양 팀의 기록과 경기 관련 정보 확인 | AI가 근거 기반 사실 정보를 균형 있게 제공 |
| 참여 준비 | 로그인, 지갑 연결, 포인트 준비 | 계정과 지갑을 연결하고 충전·민팅 상태 구분 |
| 베팅 접수 | 선택지와 금액 확인 후 서명 | EIP-712 서명 검증, 접수 및 배치 제출 |
| 체인 확정 | 참여 상태 확인 | 컨트랙트 이벤트를 인덱서가 조회용 DB에 반영 |
| 결과·수령 | 적중 배당 또는 취소 환불 수령 | 컨트랙트에서 결과 확정 후 `claimFor` 실행 |

AI는 정보 제공만 담당합니다. 승패를 추천하거나 배당, 결과 확정, 정산을 결정하지 않습니다.

## 2. 핵심 기능 — 베팅

### 상세 화면에서 서명까지

베팅 상세 화면에서는 선택지, 현재 배당, 금액 입력, 서명과 접수 상태를 한 흐름에서 확인합니다. 표시되는 예상 배당은 현재 참여 현황을 반영한 참고값이며 최종 지급액을 보장하지 않습니다.

### 서명 요청이 체인 기록이 되는 과정

1. 사용자가 선택지와 금액을 정하고 EIP-712 메시지에 서명합니다. 메시지에는 마감 시각과 재사용 방지를 위한 논스도 포함됩니다.
2. 백엔드가 서명과 잔액 등을 확인하고 요청을 접수합니다. **접수는 온체인 확정과 다른 상태**입니다.
3. 릴레이어가 여러 요청을 묶어 `PredictionMarket.placeBetBatch`로 제출하고 가스비를 부담합니다.
4. 컨트랙트가 각 요청의 서명·잔액·마감·논스 사용 여부를 검사해 예치하고, 항목별 성공 또는 거절 결과를 이벤트로 남깁니다.
5. 인덱서가 체인 로그를 읽어 조회용 DB에 반영합니다. 화면은 접수 대기(`QUEUED`)와 체인 확정(`CONFIRMED`), 거절(`REJECTED`)을 구분해 보여줍니다.

| 설계 요소 | 해결하는 문제 |
|---|---|
| EIP-712 | 사용자가 베팅 내용을 서명하고 릴레이어가 대신 제출할 수 있습니다. |
| BitmapNonce | 서명 재사용을 막으면서 여러 요청을 독립적으로 처리합니다. |
| 배치 제출 | 여러 베팅의 온체인 전송을 한 번에 묶습니다. |
| 항목별 결과 | 한 요청의 거절이 배치 전체를 되돌리지 않도록 합니다. |

## 3. 핵심 기능 — 블록체인 정산

마켓은 `OPEN` 상태에서 결과에 따라 `SETTLED` 또는 `CANCELLED`로 전환됩니다. 관리자가 경기 결과를 입력하면 컨트랙트의 `settle` 또는 `cancel` 호출로 확정됩니다. 적중자의 배당과 취소된 참여자의 환불은 서명 기반 `claimFor`로 지급됩니다.

| 컨트랙트·구성 요소 | 역할 |
|---|---|
| `PredictionMarket` | 마켓 생성, 베팅 예치, 결과 확정·취소, 배당·환불 처리 |
| `PointToken` | 참여에 사용하는 포인트 토큰의 발행·이동·소각 |
| `BitmapNonce` | 서명 요청의 재사용 방지 |
| 릴레이어 | 사용자 서명 요청의 온체인 제출 |
| 인덱서 | 체인 로그를 수집해 화면 조회 상태에 반영 |

### 체인 상태를 화면에 반영하는 경로

릴레이어는 트랜잭션을 제출하고, 인덱서는 확정된 체인 로그를 읽어 조회용 상태를 갱신합니다. 서버 DB는 화면 조회를 위한 투영이며, 베팅 예치와 결과·지급의 근거는 컨트랙트 기록입니다.

## 4. 함께 제공하는 기능

| 기능 | 사용자 경험과 처리 범위 |
|---|---|
| AI 경기 정보 | 양 팀의 기록과 근거를 사실 중심으로 보여줍니다. 예측·추천이나 정산에는 관여하지 않습니다. |
| 포인트 | 충전 요청과 토큰 민팅 확정을 구분해 진행 상태를 보여줍니다. |
| 응모 이벤트 | 마일리지로 응모하고 추첨 결과를 조회합니다. 가중 추첨은 서버에서 실행하며 결과와 재현 가능한 감사 정보를 공개합니다. |
| NFT 카드 | 사용자 이미지 결과의 CID를 바탕으로 발행 서명을 받아 `PlayerCard`를 온체인에 기록합니다. |

## 5. 시스템 구성

React 프론트엔드가 사용자 흐름을 제공하고 NestJS 백엔드가 API, 릴레이어, 인덱서를 운영합니다. Solidity 컨트랙트는 토큰과 예측 마켓을 담당합니다. AI 서비스는 경기 정보 제공으로 역할을 제한합니다.

> **시연 범위**: 개발 환경은 mock 어댑터를 이용한 화면 시연도 지원합니다. 시연 데이터는 실제 온체인 전송·확인의 증거가 아닙니다.
